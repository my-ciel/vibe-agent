# 개발자 안내

앱을 고치거나 확장하려는 사람을 위한 문서예요. 사용 방법은 [README](../README.md), 수업 운영은 [강사용 가이드](강사용_가이드.md)를 보세요.

## 개발 환경

[uv](https://docs.astral.sh/uv/)를 쓰면 가상환경을 직접 만들거나 활성화할 필요가 없어요.

```bash
uv sync --extra dev                   # 개발용 패키지(pytest)까지 설치
uv run --extra dev pytest             # 전체 테스트
uv run python launch.py               # 앱 실행 (빈 포트를 찾아 브라우저를 열어 줌)
uv run python launch.py --check       # 환경 자가진단
```

- `uv run`만 쓰면 개발용 패키지가 환경에서 빠져요. 테스트는 `--extra dev`를 붙이세요.
- 코드가 직접 import하는 외부 패키지(`openai`, `streamlit`, `httpx`, `psutil`, `pillow`)는 모두 `pyproject.toml`에 선언해 두었어요. 다른 패키지를 통해 우연히 설치되는 것에 기대지 마세요.
- 의존성을 바꾸면 `uv lock`으로 `uv.lock`도 갱신하세요.

## 화면을 가짜 모델로 확인하기

API 키 없이 화면과 승인 흐름을 볼 수 있어요.

```bash
DEMO_ROOT=/작업/폴더 uv run streamlit run tests/demo_app.py      # Windows(cmd): set DEMO_ROOT=... 후 실행
```

## 터미널에서 에이전트만 시험하기

```bash
OPENROUTER_API_KEY=sk-or-... uv run python -m vibe_agent.cli --root /작업/폴더
```

```
tools/issue_keys.py    수강생별 한도/만료 키 일괄 발급
vibe_agent/
  loop.py              재개 가능한 에이전트 루프 (승인에서 멈췄다가 이어서 진행)
  llm.py               OpenRouter 스트리밍 클라이언트, 오류 번역
  tools.py             도구: 파일 읽기/쓰기/수정, 검색, 명령 실행, 백그라운드 프로세스
  sandbox.py           작업 폴더 경계, 명령 차단 목록, 가상환경 정책
  processes.py         백그라운드 프로세스 관리 (앱 전체 공유, 남은 프로세스 정리)
  sessions.py          대화 저장/복원 (폴더별, 대화마다 파일 하나)
  history.py           모델에 보내기 전 대화 기록 점검/정리
  attachments.py       이미지·파일 첨부 처리
  platform_utils.py    OS별 차이 (셸, 인코딩, 명령 환경, 프로세스 종료)
  project_rules.py     GEMINI.md / AGENTS.md / CLAUDE.md 읽기
  prompts.py           시스템 프롬프트
  cost.py, models.py, doctor.py, errorlog.py, settings.py, ...
tests/                 pytest (가짜 모델 + 실제 프로세스, Streamlit AppTest)
```

## 설계 메모

- **승인이 실제 방어선이에요.** 파일 쓰기와 명령 실행은 항상 사용자 승인을 거치고, 파일 접근은 작업 폴더 안으로 제한돼요(`..`, 절대 경로, symlink 포함). 명령 차단 목록(`sandbox.py`)은 실수를 막는 안전망일 뿐 완벽한 보안 장치가 아니에요.
- **명령은 앱 자신의 환경과 분리돼요.** 에이전트가 실행하는 `python`이 앱의 가상환경으로 새지 않도록 `platform_utils.command_env`가 PATH를 정리하고, 작업 폴더의 `.venv`를 자동 활성화해요. 가상환경 없이 `pip install`을 하면 `sandbox.check_venv_policy`가 막아요.
- **루프는 상태를 `messages`에 모두 담아요.** Streamlit처럼 상호작용마다 스크립트가 다시 실행되는 환경에서도 `Agent` 객체만 보관하면 이어서 진행돼요. 같은 구조 덕분에 대화를 파일로 저장/복원할 수 있어요.
- **파일 덮어쓰기 충돌 방지:** 에이전트가 마지막으로 읽거나 쓴 시점의 파일 상태를 기억해서, 그 뒤에 바뀐 파일이나 읽지 않은 기존 파일은 통째로 덮어쓰지 못하게 해요(`tools.py`의 `read_state`).
- **API 키는 어디에도 저장하지 않아요.** 저장되는 것은 마지막 폴더·모델(`~/.vibe-agent/settings.json`), 대화(`~/.vibe-agent/sessions/`), 내부 오류 기록(`~/.vibe-agent/errors.log`)이에요.
- 테스트는 `tests/conftest.py`가 저장 위치를 임시 폴더로 바꿔서 실제 홈 폴더를 건드리지 않아요.

## 알려진 미검증 영역

개발은 리눅스에서 했고, 아래는 윈도우에서 직접 확인이 필요해요. 확인 항목은 [윈도우 테스트 체크리스트](윈도우_테스트_체크리스트.md)에 있어요.

- `run.bat`의 uv 설치와 PowerShell 실행 정책 환경
- 명령 실행의 `chcp 65001` 처리, `taskkill`, cp949 파일
- 서버를 띄운 채 터미널 창을 닫았을 때의 프로세스 정리
- 한글 폴더 경로에서의 대화 저장/복원
- `tools/issue_keys.py`의 실제 키 발급 (관리용 키가 필요해서 모의 응답으로만 시험했어요)
